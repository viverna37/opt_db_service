# Задача: MVP «ОптКаталог» — Telegram Mini App каталог для оптовиковТы — senior full-stack разработчик. Помоги мне с нуля построить MVP. Работаем поэтапно: после каждого этапа остановись, кратко опиши, что сделано и как проверить, и жди моего «дальше».## ПродуктОптовики (вейп-жидкости, одноразки, под-системы, испарители, картриджи, аксессуары — но в будущем любая ниша) рассылают клиентам-магазинам прайсы в Excel. Мы заменяем Excel на каталог внутри Telegram.### Клиент (магазин)- **Никакой регистрации и форм.** Пользователь открывает мини-апп в боте оптовика — сразу видит каталог. Идентифицируем его по Telegram (`initData`: id, имя, username, фото) — этого достаточно. Пользователь создаётся/обновляется автоматически при первом открытии.- Один раз при первом входе — экран-подтверждение «Мне есть 18 лет, закупаю для перепродажи» (одна кнопка, без полей). Включается/выключается в настройках тенанта.- Листает категории, ищет, фильтрует, смотрит наличие по вариантам (вкусы/цвета) и цены от объёма.- **Корзина-заявка вместо переписки.** На карточке товара у каждого варианта — степпер количества (−/+ и ввод числа). Корзина сохраняется на сервере (привязана к Telegram-пользователю и тенанту), переживает закрытие приложения и смену устройства.- Экран корзины: позиции сгруппированы по товару, количество, цена за штуку с учётом уровня цены (уровень определяется суммарным количеством всех вариантов товара в корзине; показывать подсказку «ещё 3 шт до цены от 10»), итог, поле комментария (необязательно). Варианты, которых больше нет в наличии, подсвечиваются.- Кнопка **«Отправить менеджеру»** (Telegram MainButton) → создаётся заявка (`order`) со снимком позиций и цен на момент отправки, корзина очищается. **Это не покупка: нет оплаты и оформления доставки** — менеджер связывается с клиентом сам. Никаких формулировок «купить/оплатить/оформить заказ» — только «заявка», «отправить менеджеру».- После отправки бот присылает клиенту копию заявки текстом (номер, позиции, сумма). Экран «Мои заявки» со статусами и кнопкой «Повторить» (кладёт позиции снова в корзину).- Кнопка «Спросить менеджера» на карточке — deep link на менеджера с текстом о позиции.### Админ оптовика (в том же мини-аппе, по роли)- **Заявки**: список с фильтром по статусу (новая / в работе / выполнена / отменена), карточка заявки: клиент (имя, @username, аватар, ссылка «Написать» — `https://t.me/{username}`, а если username нет — `tg://user?id=`), позиции, суммы, комментарий, смена статуса, внутренняя заметка менеджера, «Скопировать текстом» (для 1С/накладной), экспорт в Excel.- **Живые корзины**: кто что сейчас набрал, но не отправил (с временем последнего изменения) — чтобы менеджер мог напомнить клиенту. Кнопка «Напомнить» — бот отправляет клиенту сообщение «У вас в корзине N позиций» с кнопкой открыть мини-апп (не чаще раза в сутки на клиента).- **Клиенты**: все, кто открывал каталог: имя, username, первое/последнее посещение, число заявок; поле «заметка» (например «магазин Пар, Бузулук») — заполняет менеджер, не клиент; возможность заблокировать.- Уведомление в бот всем админам о новой заявке: список позиций + inline-кнопки «Взять в работу» / «Открыть в админке».- Товары, наличие, фото, категории, атрибуты, уровни цен, **загрузка Excel-прайса**, настройки.### Режим доступа (настройка тенанта)`access_mode`: `open` (по умолчанию — любой, кто открыл бота, видит каталог) | `approval` (новый пользователь видит экран «Ожидайте подтверждения», админ одобряет в разделе Клиенты одной кнопкой; никаких анкет). Часть оптовиков не хочет светить цены — это даёт им выбор без изменения кода.## Главное требование — универсальностьПриложение не должно быть захардкожено под вейп или под конкретный прайс. У каждого оптовика свои категории, характеристики и структура Excel. Поэтому:1. **Мультитенантность с первого дня.** Один бэкенд, много оптовиков (`tenant`). Все бизнес-таблицы содержат `tenant_id`, все запросы фильтруются по нему. У каждого тенанта свой бот (свой bot token) и свой slug; мини-апп открывается по `/t/{slug}`.2. **Категории — дерево** (`parent_id`, `sort_order`), создаются админом или импортом.3. **Характеристики — динамические (EAV-lite).** Таблица `attribute_definitions` на тенанта: `key`, `label`, `type` (text | number | select | bool | color), `unit` (мл, мг, Ом, мАч…), `options` для select, `scope` (product | variant), `filterable`, `show_in_list`, `sort_order`. Привязка к категориям через `category_attributes` (атрибуты наследуются от родителя). Значения храним в JSONB `attributes` у товара/варианта, индекс GIN. Фильтры в каталоге строятся автоматически из `filterable` атрибутов категории.4. **Товар → варианты.** `products` (название, бренд, категория, артикул, описание, фото, attributes, is_visible) и `variants` (название варианта — вкус/цвет/сопротивление, артикул, attributes, `stock_qty` nullable, `stock_status`: in_stock | low | out, sort_order). Товар без вариантов = один вариант по умолчанию (скрыт в UI). В корзину всегда кладётся вариант.5. **Цены по объёму — настраиваемые.** `price_tiers` на тенанта (label «от 1 шт», `min_qty`, sort_order); цены в `prices` (product_id, variant_id nullable = переопределение для варианта, tier_id, amount в копейках, integer). Количество и названия уровней у каждого оптовика свои (может быть один уровень). Расчёт цены в корзине — одна функция на бэкенде (`services/pricing.py`), фронт только отображает.6. **Бренды** — отдельная таблица на тенанта.7. **Настройки тенанта**: название, логотип, акцентный цвет, валюта, контакт менеджера (username), порог «мало» для остатков, `access_mode`, `age_gate`, минимальная сумма заявки (опционально), текст приветствия.### Корзина и заявки — модель- `tg_users` (глобально: telegram_id, имя, username, photo_url, language) и `tenant_users` (tenant_id, tg_user_id, role: owner | admin | manager | client, status: active | pending | blocked, note, first_seen, last_seen, age_confirmed_at).- `carts` (tenant_user_id, updated_at, reminded_at) + `cart_items` (cart_id, variant_id, qty). Уникальность (cart_id, variant_id).- `orders` (tenant_id, number — сквозной номер внутри тенанта, tenant_user_id, status, comment, manager_note, total, created_at, updated_at) + `order_items` — **снимок**: название товара/варианта, артикул, qty, цена, уровень, сумма (не ссылаться только на FK — товар могут удалить/переименовать).- `order_status_history` для ленты изменений.## Импорт Excel (ключевая фича)Прайсы у всех разные: заголовки категорий строкой-разделителем (часто объединённые ячейки), вкусы — отдельными строками под товаром, несколько колонок цен, иногда колонка наличия, иногда «нет в наличии» — зачёркнутым/цветом/пометкой.Сделай импорт как мастер из шагов:1. Загрузка .xlsx/.xls/.csv → парсинг (openpyxl, учитывать merged cells, выбор листа, авто-поиск строки заголовков).2. **Сопоставление колонок**: для каждой колонки выбрать роль — категория, бренд, товар, вариант, артикул, цена уровня N, остаток, наличие, атрибут X, игнорировать. Автоподстановка по эвристикам заголовков («наименование», «вкус», «цена», «опт», «кол-во», «мл», «мг»…).3. **Правила структуры**: «строка с заполненной только первой ячейкой = категория», «строки без цены под товаром = варианты», разделитель «Товар — вкус» в одной ячейке, регулярки для извлечения атрибутов из названия (например `(\d+)\s?мл`, `(\d+)\s?мг`).4. **Предпросмотр diff**: сколько товаров/вариантов будет создано, обновлено, скрыто; список ошибок по строкам.5. Применение в транзакции. Сопоставление с существующими по артикулу, иначе по нормализованному имени (lower, ё→е, без лишних пробелов). Опция «что отсутствует в новом прайсе — пометить out». Варианты не удалять физически (на них ссылаются корзины) — только скрывать.6. **Профиль импорта** (`import_profiles`) сохраняется на тенанта — следующий прайс того же оптовика загружается в один клик. История в `import_jobs` (файл, маппинг, статистика, статус).Парсер пиши как чистый, покрытый тестами модуль (`app/importer/`), независимый от FastAPI. **Первым делом проанализируй `samples/price.xlsx`** (живой прайс): опиши его структуру, какие правила нужны, и покажи, во что он превратится (категории → товары → варианты → цены). Код импорта должен работать не только на этом файле.## Стек- **Backend**: Python 3.12, FastAPI, SQLAlchemy 2.0 (async) + asyncpg, Alembic, Pydantic v2, PostgreSQL 16, openpyxl, pytest + httpx. Структура: `app/api`, `app/models`, `app/schemas`, `app/services`, `app/importer`, `app/bot`, `app/core` (config через pydantic-settings, `.env`).- **Bot**: aiogram 3, один процесс обслуживает боты всех тенантов (webhook с tenant в пути). `/start` → кнопка WebApp + установка Menu Button; уведомления админам о новых заявках с inline-кнопками; копия заявки клиенту; напоминание о корзине.- **Auth**: валидация Telegram `initData` (HMAC-SHA256 по bot token тенанта, проверка `auth_date`) → короткоживущий JWT. Регистрации нет — upsert пользователя при каждом входе. Первый владелец тенанта назначается через CLI-команду/сид. Dev-режим с фейковым пользователем для работы в браузере.- **Фото**: интерфейс хранилища (локальная папка в dev, S3-совместимое в prod), ресайз/webp через Pillow, до 5 фото на товар, первое — обложка.- **Frontend**: React 18 + TypeScript + Vite, React Router, TanStack Query (оптимистичные обновления корзины, debounce синхронизации количества), `@telegram-apps/sdk-react` (или window.Telegram.WebApp): expand, BackButton, MainButton, haptics, safe areas. Код разделить на `client/` и `admin/` зоны, общий UI-кит.- **Инфра**: docker-compose (postgres, backend, bot, frontend dev), Makefile/скрипты, сиды с демо-тенантом, ruff + mypy, README с запуском через ngrok/cloudflared для теста в Telegram.## Дизайн (макеты уже есть, следуй им)Тёмная тема, mobile-first 390px:- Фон `#111316`, поверхности `#1A1D21` / `#22262B`, границы `#2C3137`, текст `#EEF0F2`, вторичный `#A3ABB5`.- Акцент (настраивается на тенанта) по умолчанию `#8BE0B4`, текст на акценте `#0E1A14`; «мало» — `#F2BE5C`; «нет» — серый.- Шрифты: Unbounded (заголовки), Manrope (текст), JetBrains Mono (цены, артикулы).- Радиусы 12–16px, touch-targets ≥ 44px, иконки — stroke SVG.Экраны клиента (нижний таб-бар: Каталог / Корзина с бейджем количества / Мои заявки):- (однократно) подтверждение 18+;- главная: поиск, сетка категорий, «обновлено сегодня»;- категория: чипы-фильтры из атрибутов, «только в наличии», сортировка, плотный список (название, мета из `show_in_list` атрибутов, цена «от», бейдж наличия, счётчик «в корзине: N»);- карточка: фото, атрибуты-чипы, плитки уровней цен (подсвечен текущий уровень по количеству в корзине), список вариантов с точкой наличия, остатком и степпером количества; «Спросить менеджера»;- корзина: группы по товару, степперы, подсказки до следующего уровня цены, комментарий, итог, MainButton «Отправить менеджеру»;- мои заявки: список со статусами, детали, «Повторить».Экраны админа (таб-бар: Заявки / Товары / Клиенты / Настройки):- заявки: вкладки по статусам + «Живые корзины», карточка заявки (см. выше);- товары: поиск, фильтр по категории, быстрый тумблер наличия;- редактирование товара: фото, поля, динамические атрибуты по категории, цены по уровням, варианты с остатками;- клиенты: список, заметка, блокировка, (в режиме approval) одобрение;- настройки: категории-дерево, атрибуты, уровни цен, бренды, брендинг, режим доступа, **импорт прайса**;- сводка вверху раздела Заявки: новые заявки, живые корзины, товаров нет в наличии.## Этапы1. Скелет репо, docker-compose, конфиг, модели + первая миграция, сиды. **Анализ `samples/price.xlsx`** с отчётом.2. Auth через initData (без регистрации), tenant_users, роли, 18+ экран, бот: /start, Menu Button.3. API каталога (категории, товары с фильтрами по JSONB-атрибутам, поиск по trigram `pg_trgm`, пагинация) + клиентский фронт каталога.4. Корзина и заявки: API, расчёт цен, клиентские экраны корзины и «Мои заявки», уведомления в бот.5. Админ: заявки и живые корзины, CRUD товаров/вариантов/цен/фото, категории, атрибуты, уровни цен, клиенты, настройки, audit log.6. Импорт Excel: парсер + тесты на `samples/`, мастер сопоставления на фронте, предпросмотр, профили.7. Полировка: пустые состояния, скелетоны, ошибки, rate limit, README и деплой.## Правила работы- Не выдумывай требования: если что-то неясно — спроси.- Денежные суммы — integer в копейках. Все даты — UTC, `timestamptz`.- Каждый эндпоинт проверяет tenant и роль; заблокированный пользователь (и pending в режиме approval) не видит товары и цены.- Цена в заявке всегда пересчитывается на бэкенде в момент отправки, данным с фронта не доверять.- Пиши тесты на импорт, расчёт цен, auth и изоляцию тенантов.- Коммиты небольшие и осмысленные.
