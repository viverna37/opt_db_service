# ОптКаталог — контекст для Claude Code

Telegram Mini App — каталог для оптовиков (вейп, одноразки, поды,
испарители… но без хардкода ниши). Оптовики рассылают магазинам прайсы в
Excel, мы заменяем Excel каталогом внутри Telegram с корзиной-заявкой.
Полное ТЗ — `opt_promt.md`. Архитектура повторяет такси:
`opt_catalog_db_service` (этот репо, FastAPI + Postgres) → бот-сервис
(aiogram, как `taxi_tg_service`) → фронт `~/WebstormProjects/opt_catalog_app`
(React, как `raxi_app`).

## Ключевые правила

- **Мультитенантность.** Каждый оптовик — `Tenant` (свой slug, свой бот).
  Все бизнес-таблицы несут `tenant_id`, тенант берётся из заголовка
  `X-Tenant` (`app/deps.py::get_tenant`), каждый запрос репозитория
  фильтруется по нему. Тест `tests/test_tenant_isolation.py` обязателен к
  прогону при любых правках запросов.
- **Регистрации нет.** `TgUser` (глобальный Telegram-аккаунт) +
  `TenantUser` (участник тенанта: роль, статус, заметка) создаются/
  обновляются из initData при каждом запросе (`get_member`). initData
  проверяется bot token'ом ИМЕННО этого тенанта.
- **Доступ.** `get_member` — любой (нужен для `/v1/me`, чтобы показать
  экран). `get_client` — каталог/цены/корзина/заявки: отсекает blocked,
  pending (режим approval) и не подтвердивших 18+; сотрудники проходят
  всегда. `get_staff` — owner/admin/manager, `get_admin` — owner/admin
  (справочники, настройки). Ошибки доступа — `{"detail": {"code", "message"}}`,
  фронт решает по `code`.
- **Деньги** — integer в копейках. **Даты** — timestamptz UTC; часовой пояс
  тенанта (`Tenant.timezone`) только для текстов и фильтров по дате.
- **Цены** считает только `app/services/pricing.py` (чистые функции). Два
  режима уровней (`Tenant.price_basis`): `qty` — по количеству штук ТОВАРА в
  корзине (как в ТЗ), `amount` — по сумме всей заявки, уровень общий (как у
  Amigo: розница от 1 000, от 3 000 / 10 000 … ₽). Цена варианта:
  переопределение варианта → цена товара → откат к младшему уровню → к
  ближайшему старшему. В заявке цена всегда пересчитывается на бэкенде.
- **Товар → варианты.** В корзину кладётся только вариант. Товар без
  вариантов = один `Variant.is_default` (в UI скрыт). Появился именованный
  вариант — дефолтный прячется (`_sync_default_variant`).
- **Удаление.** Товары — мягко (`deleted_at`), варианты — только
  `is_visible=False` (на них ссылаются корзины). Заявки хранят снимок
  позиций (`OrderItem`).
- **Недоступные позиции** в корзине подсвечиваются (`problem=unavailable`),
  не входят ни в уровень цены, ни в итог и блокируют отправку.
- **Формулировки**: «заявка», «отправить менеджеру». Никаких
  «купить/оплатить/оформить заказ» — это не покупка.

## Уведомления

Очередь `Notification`, доставка — push-воркер внутри сервиса
(`app/services/bot_notify_service.py`), как в такси, но через бота
конкретного тенанта. Кнопка «Взять в работу» — `callback_data =
order_take:{order_id}`: бот-сервис ловит callback и дёргает
`PATCH /v1/admin/orders/{id}/status` от имени нажавшего (подписывает
initData токеном бота тенанта, как `taxi_tg_service/api_client/init_data.py`).
Бот-сервис берёт список ботов из `GET /v1/service/tenants` (`X-Service-Key`).

## Отложено

- **Импорт Excel с мастером сопоставления колонок** (из ТЗ) — не сделан.
  Есть импорт «блочных» прайсов Amigo Opt: `app/importer/block_price.py`
  (парсер) + `app/services/price_import.py` (синхронизация) + CLI
  `import-price`. Прайс Amigo — `samples/AMIGO OPT.xlsx` (в git не хранится).
- Хранилище S3 — есть только интерфейс `Storage` и `LocalStorage`.
- Миграции Alembic — как в такси, таблицы создаются `create_all` при старте.
  Меняешь схему существующей таблицы — пиши ALTER руками.
- Rate limit.
